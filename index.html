Tính năng "Phạt tiền cọc khi hủy lịch" và "Kê đơn thuốc" liên tục báo lỗi do lập trình viên backend dùng is_active BOOLEAN, không có cột lưu tiền cọc/phạt và hoàn toàn không thiết kế bảng Prescriptions!

🔍 Bảng phân tích đối chiếu (Activity Diagram vs Legacy DB)

Yêu cầu từ Activity Diagram (BA) Thiết kế cũ của Lập trình viên Đánh giá & Hậu quả Giải pháp tái cấu trúc (Optimized)
Lịch hẹn trải qua 5 bước: PENDING → CONFIRMED → CHECKED_IN → COMPLETED / CANCELLED Dùng 1 cột is_active BOOLEAN Anti-pattern nghiêm trọng: Không thể theo dõi trạng thái trung gian. Dùng ENUM('PENDING', 'CONFIRMED', 'CHECKED_IN', 'COMPLETED', 'CANCELLED')
Bệnh nhân nộp tiền cọc (Deposit) khi đặt lịch Không có cột lưu tiền cọc Kế toán không theo dõi được dòng tiền cọc của bệnh nhân. Bổ sung cột deposit_amount DECIMAL(12,2)
Nếu hủy lịch sau khi CONFIRMED, ghi nhận lý do và phạt tiền cọc Không có cột phí phạt và lý do hủy Thất thoát tài chính, không tính được tiền hoàn trả lại cho bệnh nhân. Bổ sung penalty_fee DECIMAL(12,2) và cancel_reason VARCHAR(255)
Sau khi khám xong (COMPLETED), Bác sĩ kê một đơn thuốc đi kèm Không có bảng lưu đơn thuốc Bác sĩ và dược sĩ không thể kê hoặc xuất thuốc trên phần mềm. Tạo bảng mới Prescriptions (khóa ngoại trỏ về Appointments)

🎮 Mô phỏng 2 kịch bản nghiệp vụ thực tế

👉 Nhấp vào một trong các nút kịch bản ở trên để xem quá trình chuyển đổi trạng thái và dòng tiền tương ứng.

💻 Kịch bản SQL hoàn chỉnh (healthsync_db.sql) 

-- Tái cấu trúc bảng Appointments
CREATE TABLE Appointments (
    appointment_id INT AUTO_INCREMENT PRIMARY KEY,
    patient_id INT NOT NULL,
    doctor_id INT NOT NULL,
    appointment_date DATETIME NOT NULL,
    status ENUM('PENDING', 'CONFIRMED', 'CHECKED_IN', 'COMPLETED', 'CANCELLED') 
        NOT NULL DEFAULT 'PENDING',
    deposit_amount DECIMAL(12, 2) NOT NULL DEFAULT 0.00 CHECK (deposit_amount >= 0),
    penalty_fee DECIMAL(12, 2) NOT NULL DEFAULT 0.00 CHECK (penalty_fee >= 0),
    cancel_reason VARCHAR(255) NULL,
    FOREIGN KEY (patient_id) REFERENCES Patients(patient_id),
    FOREIGN KEY (doctor_id) REFERENCES Doctors(doctor_id),
    CONSTRAINT chk_penalty CHECK (penalty_fee <= deposit_amount)
);

-- Tạo bảng mới Prescriptions
CREATE TABLE Prescriptions (
    prescription_id INT AUTO_INCREMENT PRIMARY KEY,
    appointment_id INT NOT NULL UNIQUE,
    medication_details TEXT NOT NULL,
    doctor_notes TEXT NULL,
    issued_date DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (appointment_id) REFERENCES Appointments(appointment_id) ON DELETE CASCADE
);

-- Trigger chặn kê đơn cho lịch hẹn chưa COMPLETED
DELIMITER //
CREATE TRIGGER trg_check_prescription_eligibility
BEFORE INSERT ON Prescriptions
FOR EACH ROW
BEGIN
    DECLARE v_status VARCHAR(20);
    SELECT status INTO v_status FROM Appointments WHERE appointment_id = NEW.appointment_id;
    IF v_status != 'COMPLETED' THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Lỗi nghiệp vụ: Chỉ được kê đơn thuốc cho lịch hẹn có trạng thái COMPLETED!';
    END IF;
END //
DELIMITER ;
